# login

BORUIX 的**登录认证程序**：读取用户名与口令，校验通过后**降权**到目标用户，再切换到该用户的 shell。

[English](README.en.md)

## 它做什么

```
读用户名与口令 → 校验 → 降权到目标用户 → 切换到该用户的 shell
```

它是**独立的用户态程序**，不是系统初始化进程的内联逻辑。把终端读写、口令读取、降权都塞进 PID 1
会让它同时承担"进程监督"与"认证"两件事，任一出错都影响系统存活。

## 身份来自只读的权威文件

用户的身份（用户 ID、组 ID）**一律取自系统配置文件**，**绝不**读用户态可写的账户表。

理由直接：账户表用户态可写。如果身份以它为准，那么**改一下那个文件就等于冒充别人**。

## 校验失败的处理

| 规则 | 说明 |
| --- | --- |
| 最多 **3 次** | 具名常量而非魔法数 |
| 失败信息**统一** | 不区分"用户不存在"与"口令错误"，避免用户名枚举 |
| 耗尽后退出非零 | **绝不在失败时降权**——否则等于把 shell 交给一个没通过认证的人 |

## 权限

本程序运行时所持的权限是**实测确定**的，不是推断：

| 需要 | 原因 |
| --- | --- |
| 读口令文件 | 因为它的身份就是文件属主，**以属主命中**读取，不需要任何权限覆盖能力 |
| **必须能降权** | 降权本身是受限操作，没有相应权限就无法把身份降下来 |
| **不得持"拥有者覆盖"能力** | 实测该能力会**完全绕过**权限策略求值——持它则口令文件形同虚设 |

### 一处如实承认的风险

"某些权限可以间接成为读取口令文件的通道"这个担忧**是真的**。但对本程序**不构成新增风险**：
它**本来就是**口令文件的属主，无需任何额外权限就能读；而所持的那项权限只影响**降权**，
**不影响文件访问策略**。故对本程序而言，该权限的**唯一**作用就是"允许把身份降下去"。

降权与撤权在**同一次**操作内完成，不存在"已降权但仍持有该权限"的中间状态。

> 这一点**修正**了早期设计中"登录程序不得持该权限"的禁令——该禁令与"无此权限则无法降权"的
> 规则**直接冲突，两者不可能同时满足**。

## 诚实边界

### 口令回显：已关闭

输入口令时**任何字符都不上屏**。该能力由用户态库 [`libline`](https://github.com/BRX-Boruix/libline) 提供——**内核一行未改**，
也不引入终端控制接口。

**验证方式**：在真实虚拟机中经键盘键入口令，串口日志里**不出现**口令明文，而用户名逐字回显。

### 只取"回显抑制"这一个子集

本程序**不背**历史记录与 Tab 补全。这不是口头约定：行编辑组件的功能在那里被裁到最小集，
**历史与补全在这条路径上编译期可见地不可达**。

### 未实现的部分

| 项目 | 状态 |
| --- | --- |
| 失败次数锁定 | **无**——不实现 PAM 式的失败锁定 |
| 超时 | **无**——输入不设时限 |

## 构建

```bash
cargo build --release
```

由系统初始化进程在提供终端时拉起。

## 文件结构

```
login/
├── Cargo.toml    # 包定义
├── build.rs      # 注入链接脚本
├── linker.ld     # 用户态段布局
└── src/
    └── main.rs   # 身份读取、口令校验与降权
```
